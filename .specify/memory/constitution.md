# Magus World Constitution

## Core Principles

### I. Decoupled Architecture
The agent's "brain" must be completely decoupled from the terminal interface. The game loop, the player input handling, and the agent's evaluation engine MUST operate as distinct modules. This approach ensures that if the engine is eventually wrapped in a REST API, deployed as a microservice, or the terminal is swapped for a web UI, the core logic remains unchanged.

### II. Safe Board State Management
The agent MUST rely on continuous evaluation loops with rigorous board state management. When the agent calculates future moves (looking ahead multiple turns), it MUST operate on isolated copies of the board state or safely use python-chess operations. The actual live game state must never be accidentally mutated during evaluation.
  
### III. Computational Efficiency (NON-NEGOTIABLE) 
Chess engines are computationally expensive. All move generation and evaluation functions MUST prioritize efficient data structures and optimal time complexity. Whether traversing decision trees or evaluating board positions, algorithms must remain tightly optimized to prevent the terminal from freezing during agent calculations.

### IV. Swappable Decision Engine
The decision-making module MUST be designed for easy substitution. Code structure MUST allow an external Large Language Model or a more complex autonomous workflow to be plugged in later without disrupting existing implementation. The evaluation interface must remain stable.

### V. Comprehensive Testing for Edge Cases
Chess has notorious edge cases. All core logic MUST have unit tests, particularly focusing on move validation, en passant, castling rights, and draw conditions (three-fold repetition, stalemates). Test coverage drives correctness.

## Governance

### Spec-First Execution
Before a single line of code is written or modified, the feature MUST be formally defined in the project specification using the toolkit. This ensures the AI always has a concrete, version-controlled source of truth to reference, eliminating unpredictable, ad-hoc development from the cycle.

### Rigorous State and Evaluation Integrity
When building autonomous workflows that rely on continuous evaluation loops and precise state management, strict control over decision cycles is MANDATORY. Any modifications to the agent's evaluation functions or board state logic MUST pass automated regression tests before acceptance, ensuring the engine never degrades in performance or violates chess rules.

### AI Code Accountability
Treat the AI assistant as a highly capable but unsupervised junior developer. Every block of implementation code generated by the toolkit MUST be manually reviewed for algorithmic efficiency and correctness. All commits MUST follow conventional format to clearly track codebase evolution.

### Interface and Dependency Isolation
Any external tools, libraries, or future model integrations MUST be strictly isolated. Dependencies like python-chess MUST be wrapped in abstract interfaces, protecting the core game engine from unexpected breaking changes. This ensures swapping underlying technology later won't affect the rest of the application.
